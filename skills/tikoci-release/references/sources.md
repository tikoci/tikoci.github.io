# Sources

The rules in [tikoci-release](../SKILL.md) come from the November 2026
survey of tikoci instruction files and skills. Row ids refer to
[2026-11-survey.tsv](https://github.com/tikoci/tikoci.github.io/blob/main/docs/house/2026-11-survey.tsv);
settled disagreements are in
[2026-11-conflicts.tsv](https://github.com/tikoci/tikoci.github.io/blob/main/docs/house/2026-11-conflicts.tsv).
Planning: Phase 3 of [issue #21](https://github.com/tikoci/tikoci.github.io/issues/21).

| Rule | Rows | Notes |
| --- | --- | --- |
| Any artifact: one CI path, committed or run-derived versions, fixed build identities, channels move only onto what was tested on the shipped commit | - | Maintainer, 2026-11-17 (review of #37): an npm `latest` release is a person's call; dispatching previews is a step toward scheduled `next` publishes; a repackaging image may promote from CI once its tests are robust. app-t3code review of #37 (the invariant over the trigger). The container release side is tracked in #21. |
| SemVer; a 0.x breaking change bumps the minor | quickchr-016 | quickchr `CONTRIBUTING.md`, "Releasing". |
| The committed version picks the channel | rosetta-46, centrs-17 | Settles `release-channel` (maintainer, 2026-11-17). rosetta `npm-channel-source-of-truth.instructions.md`: no input may also select the channel; unknown shapes fail. centrs `ci-test-tiers-and-release-versioning.instructions.md`: the prerelease identifier selects the dist-tag, though a `channel` input picks the run. quickchr chooses the dist-tag at dispatch (`npm-tag`, `scripts/release-prep.ts`: "never inferred from the version") and publishes plain versions to `next`. |
| `X.Y.Z-next.<run number>`, written in the runner only | centrs-17, rosetta-42 | centrs (`0.1.9-next.23`); rosetta "Determine npm release channel" appends `$GITHUB_RUN_NUMBER` and never commits it. |
| `next` never lags `latest`, and neither channel moves backwards | quickchr-114 | quickchr `release.yml` moves trailing dist-tags after publish and refuses a version older than `latest`; centrs moves `next` on a `latest` release; rosetta "Verify prerelease is ahead of latest and next". Comparing against `next` too, and moving `next` only forward: quickchr review of #37 (a renamed workflow restarts the run number; centrs's file is `release.yaml`). |
| `latest` is a fresh publish, not a promoted preview | quickchr-016 | quickchr `ci.instructions.md` "Release Process" promotes the tested `next` version with `npm dist-tag add … latest`; centrs never did (review of #37). The trade is stated, with no `gitHead` guard. |
| Who raises `X.Y.Z-next`; `release-plan.ts check` in `bun run check` | centrs-18 | centrs: "the first change after a stable cut adds `## 0.1.10 — next` and sets `0.1.10-next`". The offline check: quickchr review of #37. |
| A preview needs no commit, tag or Release | centrs-17 | centrs: "It needs no commit, PR, git tag or GitHub Release". rosetta makes a prerelease GitHub Release for previews, which carry its database assets. |
| Every user-visible change adds a bullet in the same PR | rosetta-26, quickchr-015 | Settled `changelog-unit`. What counts follows rosetta `changelog-discipline.instructions.md` and its `CHANGELOG.md` header. |
| One section per stable version, `## X.Y.Z — next` | centrs-18 | Settles `changelog-heading` (maintainer, 2026-11-17). centrs `CHANGELOG.md` and #485. quickchr and rosetta use `## [Unreleased]`. |
| No reference-link footer | rosetta-26 | rosetta: a promotion without its link definition renders literal brackets; "No automated check catches this". |
| A person bumps and dates; CI never writes or pushes | rosetta-42, quickchr-114 | rosetta `manual-version-bump.instructions.md` (the removed `bump-version` job); quickchr `release.yml`: "Release CI never updates package.json or CHANGELOG.md". lsp-routeros-ts commits a bump after publish today. |
| Dispatch-only from main, dry run, one concurrency group | quickchr-114, centrs-17 | quickchr `release.yml` (`concurrency: release`, `cancel-in-progress: false`); centrs `release.yaml`. |
| Gates on the commit that ships; the device bar for that exact commit | quickchr-114, centrs-17 | centrs: "The release publishes the commit the dispatch ran on, never an older green one, because npm provenance attests `GITHUB_SHA`." centrs reuses the nightly sweep of that commit; a dry run reports the bar without waiting ("a green dry run is not a QA result", centrs `release.yaml`). quickchr's `scripts/ci-freshness.ts` reads the newest completed run and only warns when main is ahead (quickchr review of #37). |
| `bun run check` and `bun run audit` before anything ships | - | Settled `audit-gating` (tikoci.github.io #33). No release workflow surveyed runs the audit today. One audit script for CI and release, and the full gate rather than lint: quickchr and centrs reviews of #37 (tikoci-toolchain, "CI calls the same entry point"); centrs's release gate is `bun run ci` (`lint:ci && test && build`). |
| Pack, smoke-test and publish that tarball | - | quickchr and centrs reviews of #37: quickchr ships `src` through a `files` allowlist, and no release checks the tarball; centrs's dry run runs `npm pack --dry-run`. The smoke step was run on a sample package, failing when `files` left out an imported module (2026-11-17). Publishing a tarball through trusted publishing is untested. |
| Decisions in a unit-tested script | centrs-17 | centrs `scripts/release-plan.ts`; quickchr `scripts/release-prep.ts`; rosetta `scripts/release-notes.ts`. `release-plan.example.ts` was run with 13 unit cases and against the live registry (2026-11-17). |
| Bounded retry of idempotent calls after publishing, then the repair | quickchr-114 | quickchr `release.yml`, "Move trailing dist-tags onto this version" (three tries, 10 s and 20 s). Framed as outside tikoci-ci's retry rule, and limited to idempotent calls (`gh release create` checks for the release first): centrs review of #37. Loops run against stubs. |
| An idempotent publish, so "Re-run failed jobs" finishes a run | - | quickchr review of #37, round 2: a re-run keeps `run_number`, and `npm publish` of an existing version fails before the later steps. `npm view <name>@<version> dist.integrity` exits 1 with `E404` for a missing version on npm 11.20.0 and 12.2.2; `npm pack --json` reports `integrity` on both. Tested against stubs (same tarball, different contents, absent, registry error). Reading the channel again before `npm publish` and each `npm dist-tag add`, so a re-run with an old plan never moves a channel backwards; creating the tag at the commit and checking an existing one before `gh release create --verify-tag`: CodeRabbit review of #37. Tested against stubs. Checking `latest` before every publish, not only the channel, and failing on a leftover draft release instead of counting it as done: Copilot review of #37. |
| A bad release: deprecate, point `latest` back, never unpublish | - | centrs review of #37. |
| `run-name`; keep the workflow file name | - | centrs `release.yaml` `run-name`; quickchr review of #37 on renames. |
| The workflow is the only publishing path | rosetta-49 | rosetta `release-via-ci.instructions.md`. |
| Trusted publishing, from a main-only environment | - | Settles `npm-auth` (maintainer, 2026-11-17). [npm docs](https://docs.npmjs.com/trusted-publishers), read 2026-11-17: npm 11.5.1 and Node 22.14.0; "Allowed actions": `npm stage publish` always, and a configuration created since 2026-09-03 allows direct `npm publish` only when chosen (Codex review of #37); dist-tags over OIDC need 11.21.0 on 11.x and 12.2.0 on 12.x (Codex re-review of #37, npm 12.2.0 changelog) and "Allow npm dist-tag", off by default; npm 12 changed `npm pack --json` from an array to an object keyed by name (npm 12.0.0 changelog); GitHub-hosted runners only; automatic provenance for public repos; `repository.url` must match. Node 26.13.1 bundles npm 11.20.0 (nodejs.org dist index). quickchr, centrs and rosetta use `NPM_TOKEN`; rosetta publishes without `--provenance`. A main-only environment named in the trusted publisher: quickchr review of #37 (a branch can edit the workflow file); centrs: today a branch dispatch gets the org `NPM_TOKEN`. Setup steps in `npm-trusted-publishing.md`. |
| npm as a devDependency, not `npm install -g` | - | zizmor 1.32.0 `adhoc-packages` flags a global install; quickchr runs `bunx npm publish`. centrs review of #37: `bun add -d npm` under Bun 1.4.4 runs `node_modules/.bin/npm` (12.2.2); npm 12.2.2 declares Node 22.22.2+, 24.15.0+ or 26+ in `engines` (registry). |
| Immutable releases, with exceptions | mikropkl-24 | Settles `immutable-releases` (maintainer, 2026-11-17). [GitHub docs](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases); GA 2025-10-28. mikropkl `refresh-scripts.yaml` uploads fixed assets with `--clobber`; rosetta `republish_assets`. |
| Tag ruleset for `v*` | - | From the #21 3c research. `GITHUB_TOKEN` cannot be a ruleset bypass actor (`protection-kind`). |
| VS Code: odd minor for pre-release | - | [VS Code docs](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#pre-release-extensions): "semver pre-release tags are not supported". lsp-routeros-ts uses the odd minor. |
